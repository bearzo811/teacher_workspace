# 【工程】多人服務架構提案

日期：2026-11-11｜狀態：規劃提案，尚未授權實作。

依收益減成本排序；星號為相對工程判斷，不是工期或報價。已確認的產品方向見 `Product_Plan.md`，具體設計在各里程碑展開。

## P1：獨立新版環境與舊站基準

- 標記：立即｜收益 ★★★★★｜成本 ★★｜影響：中｜階段 M0。
- 建立新版部署、DB、Auth 與測試資料邊界，保存舊站回歸基準。
- 驗收：新版不能寫入舊 DB；部署與 Cron 密鑰不同，舊班日常不中斷。

## P2：明確班級上下文與資料隔離

- 標記：立即｜收益 ★★★★★｜成本 ★★★★★｜影響：大｜階段 M1。
- 所有領域建立班級歸屬，學期型資料有學期歸屬；班級、學生及外鍵不可跨班；快取、設定、唯一鍵、匯出與排程一起改。
- 驗收：雙教師／雙班負向測試與連線池上下文隔離測試通過，任何一般請求不可透過資料庫管理角色繞過隔離。
- 前置：P1。雖然成本高，仍是不能略過的發布阻擋項。

## P3：Google 登入與邀請資格

- 標記：立即｜收益 ★★★★★｜成本 ★★★｜影響：中｜階段 M1。
- 建議 Supabase Auth；產品另外驗證邀請、班級所有權與一人一使用中班級。
- 驗收：Google 登入成功但未受邀，仍無法讀取／建立班級；邀請不可重複占用。

## P4：可撤銷的班級大屏裝置授權

- 標記：立即｜收益 ★★★★★｜成本 ★★★｜影響：中｜階段 M2。
- 一次性配對，班級範圍憑證，伺服器執行學生操作白名單。
- 驗收：未配對、過期配對碼、撤銷裝置與跨班 ID 全部被拒絕；正常白板不需學生登入。

## P5：示範／引導／可調整規則與小班排班

- 標記：立即｜收益 ★★★★｜成本 ★★★★｜影響：大｜階段 M3。
- 示範資料隔離；規則確認才啟用；值日模板、名額與可兼任設定；1／9／15 人 UX。
- 驗收：新老師自行完成啟用，無人力不足時的假成功，代班與公平性有可解釋紀錄。

## P6：備份、限時支援、刪除生命週期與紀錄

- 標記：立即｜收益 ★★★★★｜成本 ★★★★｜影響：大｜階段 M4。
- 每日備份目標、隔離還原、30 天刪除還原期、授權支援與到期撤銷、限流與監控。
- 驗收：實際還原演練；停用／刪除期間不繼續扣點；支援期間外不能取得學生內容。

## P7：有界元件拆分與共同寫入回饋

- 標記：立即（改造所需範圍）｜收益 ★★★★｜成本 ★★★｜影響：中｜階段 M1～M3。
- 依模組拆分大屏與班級資料操作，保留既有能力；不用新框架重寫所有頁面。
- 驗收：各模組能獨立測試，無新增重複授權規則，失敗回饋一致。

## 排序之外的架構選項

推薦：共享資料庫／資料表＋班級隔離。最符合單一網站、3～5 位老師與統一更新的目標，前提是完成 P2。

備選：每班獨立 schema／資料庫。實體邊界明確，但 schema 更新、連線與備份維運成本較高；不當作第一階段預設，也不把它與「每位老師自行部署」混為一談。

下一版：學校／共同教師、40 人班、學生帳號與手機完整後台。可不改：在未有負載證據前，不導入微服務或另換前端框架。

實作順序為 P1 → P2 與 P3 → P4 → P5／P6 → 整合驗收。收益排序不取代依賴順序。產品決策已確認不等於 P1～P7 程式改造已開始。
