# Teacher Workspace 多班級服務試用計畫

日期：2026-11-12（台灣時間）｜版本：規劃 v2｜狀態：M1 開發中

## 2026-11-12 決策修訂（優先於下方 v1 歷史內容）

取消系統邀請碼、邀請名單及人工核准。Google 首次登入直接註冊，測試群組由線下通知；使用者接受網址被轉傳與小範圍公開註冊的風險。仍限制一人一個使用中班級、15 位學生，保留後端資料隔離與基本用量限制。未登入與停用帳號不得操作班級。M1 改為「登入、註冊、班級與資料隔離」。以下提及「未受邀拒絕、自由註冊不納入」等 v1 條件不再適用，歷史架構評估與驗收清單亦以此修訂為準。舊邀請 SQL 未執行，已移除，不得執行殘留草稿。

## 【PM】產品主軸

學生在教室自主完成任務，透過點數、等級與商店獲得回饋，讓老師減少追蹤、提醒與處理班務的時間。A（減少班務）、B（學生自主）、C（獎勵參與）三者都保留，以同一條日常流程呈現，不拆成三套產品。

## 【PM】已確認的 20 項決策

1. 由老師個人註冊、建立及管理班級，第一階段不做學校管理員。
2. 每位老師一個使用中的班級，保留歷史學期資料。
3. 以 Google 帳號開放註冊，不做系統邀請名單或人工核准，線下通知測試群組。
4. Google 首次登入自動註冊；後端驗證身分及帳號是否停用。
5. 白板由老師配對一次，之後直接開啟；老師可撤銷授權。
6. 學生僅在配對的大屏按座號使用，不建立學生帳號，不開放在家操作。
7. 班級由建立者單獨管理，第一階段不做協同教師權限。
8. 邀請試用免費，不開發付款功能。
9. 現有單班站繼續使用，新版沿用程式但在獨立環境開發；穩定後再規劃搬移。
10. 保留目前可用功能，第一階段不另外增加新業務模組；保留老師可關閉不需要功能的能力。
11. 提供可調整的規則範本，老師預覽並確認後才啟用。
12. 首批邀請 3～5 位導師。
13. 首版支援 15 人以內小班，暫不承諾一般 40 人班。
14. 值日工作名稱及所需人數可自訂，系統公平輪排。
15. 提供獨立示範模式，再引導老師建立正式班級；示範資料不混入正式資料。
16. 電腦、平板完整操作；手機先支援查看與簡單勾選。
17. 平台平常只查看系統狀態；查看班級內容需老師限時授權，留下存取紀錄。
18. 每日自動備份、提供手動匯出；嚴重故障的資料復原目標為最多回到前一天。這是規劃目標，不是已提供的服務保證。
19. 主動刪除班級／帳號後提供 30 天還原期；期滿清除正式資料，備份依獨立保存週期清除。
20. 產品同時主打減少班務時間、學生自主與獎勵參與；不是三選一。

## 【PM】首版保留範圍

- 聯絡簿與作業：每日編輯、繳交日、四態追蹤、個別限制、欠繳排序、紙本清單、簿本管理。
- 護照與閱讀：國英護照、閱讀／讀報、到期規則、獎勵與逾期結算。
- 班級生活：獨立出缺席、每日任務、返校日、行事曆、自訂值日、代班與老師確認獎勵。
- 點數與商店：金幣、XP、等級、商品等級門檻、購買、背包、老師管理與核銷。
- 大屏：現有六分頁、分頁開關、學生自助、個人優先任務、午餐影音與任務回饋、字級設定。
- 老師工具：學生管理、學期設定、資料匯出、備份及檢查。

「保留目前功能」不代表重新啟用已隱藏的課程計劃或已取消的舊長期任務，也不代表沿用目前公開免授權的 API。顯示開關與操作權限分開處理。

## 【工程】架構方向（提案，尚未實作）

- 保留 Next.js、React、TypeScript、Drizzle／PostgreSQL 技術主體，不重寫所有畫面。
- 以 Supabase Auth 處理 Google 登入；身分驗證與班級操作授權分開驗證，不再設產品邀請閘門。
- 新版建立獨立部署、資料庫、OAuth callback 與測試環境；不得沿用舊正式資料庫連線、cookie 簽章密鑰、Cron 密鑰。
- 採同一服務、共享資料表、明確班級歸屬的資料模型。第一階段一老師一有效班級，資料層保留未來學校與共同管理的擴充空間，但不先做相關 UI。
- 伺服器從已驗證登入／裝置取得班級範圍，不相信前端傳入的班級或學生 ID；所有子資料與外鍵關係檢查必須同班。
- 查詢、更新、匯出、紙本清單、快取、檔案、排程、點數帳本與備份都必須具有班級範圍；學期型紀錄也須有正確學期歸屬。
- 班級設定與獎勵規則改成逐班儲存；禁止沿用全域單列設定與共用 `default` 獎勵規則。
- 資料庫採最小權限與適合連線方式的 RLS／授權防線。若保留伺服器直接連線，須證明使用角色與連線池不會繞過或洩漏授權上下文，不能只開 RLS 就視為完成。
- 裝置配對採一次性配對碼；常駐授權憑證限定班級、可撤銷，敏感憑證不放在永久網址。配對期限與數量在技術設計中給出具體建議，不視為已確認規則。
- 白板是共享裝置：配對驗證的是裝置與班級，不宣稱能辨識按座號者本人。學生可執行動作採伺服器白名單，不能改老師專用設定或核銷權限。

## 【工程】開發里程碑與依賴

### M0：隔離環境與保留舊站

工作：建立新版開發分支與獨立專案設定，記錄舊站基準、資料與環境界線；整理核心流程回歸清單，只使用合成／去識別示範資料初始化新版。

完成條件：新版測試無法寫入舊站；新舊 cookie、資料庫與排程不互通。舊站維持原本功能。若需要付費方案或新權限，再依具體配置取得授權，不先自動購買。

### M1：登入、註冊、班級與資料隔離

依賴：M0。

工作：Google 登入與自動註冊；老師與班級模型；一人一使用中班級及 15 人限制；所有領域資料、唯一鍵與查詢範圍改造；學期紀錄、班級版號與快取分離。

完成條件：使用 A／B 兩位老師及兩班資料，證明正常與惡意替換 ID 的讀取、寫入、匯出、商品購買、核銷、快取、逾期結算皆不串班；未登入與停用帳號不能操作班級；第 16 位學生由後端拒絕，不能只隱藏按鈕。

### M2：大屏配對與學生操作權限

依賴：M1。

工作：配對、重開續用、撤銷；移除新版匿名讀寫捷徑；教室任務白名單；保留點座號與快速回饋；畫面設定與操作授權分離。

完成條件：未配對／已撤銷裝置不能取得學生資料或寫入；A 班裝置不能操作 B 班；配對碼不可重複兌換；教師、裝置與未登入三種角色的 API 測試通過。正常白板續用不要求學生每天登入。

### M3：小班設定、值日與首次使用

依賴：M1、M2。

工作：示範模式；建立班級／名冊／學期／規則引導；老師確認規則；自訂值日工作與人數；代班適配；15 人以內白板排版；電腦／平板完整後台與手機基本操作。

完成條件：新老師能自行完成引導到白板配對；示範操作不改正式金幣或名冊；以 1、9、15 人與缺席情境測試，不接受無限縮小字體。值日工作需求超過可用人力時，顯示原因並讓老師處理，不假裝排班成功。

公平輪排工程提案：分開計算不同工作類型的實際負擔，優先分給累積負擔較少者，平手採可重現的輪序；抬餐桶等平行工作是否可兼任由設定決定。缺席、代班與人工交換保留紀錄。具體權重與超額處理須在該階段呈現預覽再確認，尚未將某套公式當作產品既定規則。

### M4：維運、隱私與資料生命週期

依賴：M1；與 M3 可在程式邊界明確後交錯進行。

工作：每日自動備份、手動匯出、還原演練；30 天還原期；到期清除與備份保留政策；登入／裝置／API 限流；錯誤與用量監控；老師啟用、到期與撤銷的限時支援；操作與支援存取紀錄；隱私告知與學校使用情境檢核。

完成條件：備份有成功／失敗訊號；還原到隔離環境並驗證資料與點數，不直接覆蓋其他班級；刪除中的班級停止學生操作與扣點；還原不重複執行已發放獎勵；支援權限由後端控管、到期失效。將「資料可回到前一天」和「修復需要多久」分開記錄，後者尚未承諾。

### M5：整合驗收與邀請試用

依賴：M1～M4 所有立即項目通過。

工作：以完整一天情境驗證全模組；雙班並行、連點、斷線、重試、排程重跑、換學期與跨年；白板 1280×720 有效尺寸與 3840×2160；教學導覽；邀請 3～5 位導師，記錄問題、使用阻礙與老師節省時間的回饋。

完成條件：無已知跨班存取、未授權學生資料曝露、重複發扣點或庫存錯誤；裝置撤銷與備份還原演練通過。原有單班正式站尚不自動搬入。

## 【工程】效能驗收提案

在約定測試裝置、網路與 3～5 班負載下量測，而非只看畫面動畫。暫定目標：點擊可見回饋 ≤100ms、一般寫入 P95 ≤2 秒、核心頁首次可操作 ≤3 秒；實作前先量測並確認基準。寫入失敗必須顯示失敗或還原，不得用樂觀畫面冒充已保存。這些是工程提案，尚非使用者已確認的 SLA。

## 【PM】暫不納入

- 付費、非 Google 註冊、學校管理員、共同管理、多個使用中班級。
- 學生個人帳號、在家操作、40 人以上班級、手機全功能後台。
- 直接切換你班上的正式站、直接把正式學生資料複製到示範環境。

## 【工程】舊站日後搬移

新版穩定後才建立獨立搬移任務：盤點與備份 → 隔離環境演練 → 比對學生、作業、學期、點數帳本與背包 → 約定切換時間 → 暫停舊站寫入及扣點排程 → 最終匯入 → 驗證 → 啟用新版。回復時只允許一個站成為寫入來源，避免雙邊繼續發扣點。搬移時間與正式執行尚未授權。
