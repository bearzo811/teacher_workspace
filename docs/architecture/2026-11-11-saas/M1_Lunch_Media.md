Teacher page `/workspace/lunch-media` stores one canonical YouTube video ID plus an optional 120-character title per class. Only the class owner may set/stop; optimistic version and request receipts prevent stale edits or duplicate updates. Public tables have owner RLS and no direct anonymous access. Paired whiteboards read their own class's current video and may only clear the exact version on finish. They cannot select a new video. Revoked devices and cross-class teachers are denied; no student rewards, balances, inventory or learning records change.

Lunch work/task data and initial media snapshot load in parallel. With a video the player fills available space and work/tasks are hidden; without a video the existing left-work/right-task layout returns. While the lunch page is visible, a private no-store same-origin endpoint checks changes every 10 seconds. The official iframe API reports ended; the clear request is version-checked, then fetches current media so an old ended event cannot erase a newer song. Clear failure offers retry; blocked autoplay and unembeddable videos have explicit guidance. No iframe is loaded when the class has no selected video.

The legacy `listType=search` fallback is not copied. YouTube discontinued embedded search playlists in November 2020: https://developers.google.com/youtube/player_parameters . Playback requires a concrete video link; the song title is a note. Official state-change and autoplay-blocked behavior: https://developers.google.com/youtube/iframe_api_reference . Teacher UI explains the YouTube connection and possible manual-play requirement. No Data API key/search quota is introduced.

Local tests cover allowed hosts and video forms, hostile/invalid URLs and arbitrary iframe rejection, bounded snapshots, stale asynchronous responses, owner/anonymous/class isolation, module/revocation gates, set retry/conflict, and stale/double finish.
