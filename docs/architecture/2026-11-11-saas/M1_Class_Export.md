These are configuration checks; they do not prove physical screen legibility, touch/audio, student transactions or complete duty coverage. Read errors hide the results and download controls. Recent export receipts mean generated, not successfully saved on a user's disk.

`export_pilot_class(class)` requires the active Google teacher owning the active class, independent of optional module switches. Its explicit allowlist contains 53 business tables through schema revision 0041, including recoverable archived students and histories. Term-scoped day overrides are filtered via own terms. It excludes teacher identities, auth/session storage, the device table (including pairing/token hashes), private worker context and export metadata. Audit actor/device UUID references remain as historical references; the file cannot be blindly inserted into a fresh database. Restore needs explicit identity/device tombstone mapping and validation before it can be offered.

All business rows are collected by one SQL statement for a single MVCC snapshot. It serializes with class changes, rejects above 3 MiB/50,000 rows without truncation or a success receipt, and limits repeated generation to one per 30 seconds per class. SHA-256 is computed over exact PostgreSQL UTF-8 JSON bytes. The application validates format/class/export ID/counts/size and recomputes the hash; the browser verifies the downloaded bytes again before initiating the file download. No reserialization changes the byte-exact payload.

The POST download endpoint checks same-origin and teacher authentication. It returns an attachment with private/no-store and nosniff headers. No anonymous/paired-device export is granted. Cloud stores only generation metadata: actor/class, timestamp, counts, byte length and SHA-256, not the exported payload. Downloaded files contain student information; teacher UI explains local safekeeping, limits, and that actual saving/restore is not certified by a generation receipt.
