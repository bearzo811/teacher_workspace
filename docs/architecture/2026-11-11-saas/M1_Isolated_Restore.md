# 本機隔離還原驗證

2026-11-26：新增 `pilot/scripts/verify-class-export.ts`，只接受本機匯出檔及匯出紀錄中的 SHA-256。每次建立全新的 PGlite 記憶體資料庫，結束即關閉，沒有雲端連線參數、遠端寫入或網頁還原入口。

執行方式（專案根目錄）：

```sh
node --import tsx pilot/scripts/verify-class-export.ts /absolute/path/export.json SHA256_FROM_EXPORT_RECEIPT
```

先驗證原始 UTF-8 位元組指紋、格式、容量、筆數與帳本，再套用 0001–0042 業務結構（不建立 0021 雲端排程）。要求完整 53 張業務表與精確欄位；保留原始 JSON 傳入資料庫，避免 JavaScript 轉換造成 bigint 精度遺失。暫緩外鍵於同一交易結尾核對，逐表比對全部還原資料，重設 identity sequence。

登入資料不在匯出中。歷史老師參照以停用身分占位，裝置以已撤銷、沒有憑證的紀錄占位；班級擁有者改為新的停用占位。還原時停用業務觸發器，避免重發獎勵或改寫歷史，但保留外鍵與約束檢查。驗證完不留下可登入帳號或有效裝置。

自動測試涵蓋三組完整虛構快照：學習與獎勵、購買與背包、值日與代班。逐表資料一致、已移除學生保留、缺失外鍵拒絕、錯誤指紋拒絕、部分視覺測試快照拒絕，並包含超過 JavaScript 安全整數的歷史流水號 9007199254740993。

檔案命令列實測亦通過：值日快照 294 筆／10 位學生、學習快照 246 筆／16 位學生、商店快照 106 筆／3 位學生，各有 53 張表、126 項外鍵；全部 businessDataMatches=true、restoresLoginAccess=false。這裡的 294 筆虛構值日快照與使用者的 2 位學生雲端檔不同。全套 48 項測試及 production build 通過。

此工具只證明快照可放入隔離業務結構，尚未證明重新登入後所有介面流程或正式災難復原程序。使用者已確認的 294 筆雲端匯出檔未提供給工具，不能把虛構測試結果當成該檔實際還原成功。尚需真實匯出檔隔離演練、權限重新綁定設計、還原後介面驗收，以及加密自動備份、保留政策與告警。

後續操作探針：恢復業務觸發器後，以 anon 與無綁定 authenticated 身分逐表確認不可見資料（無讀取權或零筆）。另外只在本機可回滾交易中暫時啟用占位老師，透過正式 RLS 讀取完整名冊（包括已移除學生），呼叫正式匯出 RPC 並確認全部業務資料與原檔相同。測試結束回滾暫時啟用及新產生的匯出紀錄，再確認沒有有效登入或裝置。這是資料庫操作探針，不是瀏覽器登入或全部學生互動流程的驗收。
